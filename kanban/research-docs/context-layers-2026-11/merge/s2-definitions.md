## What the terms mean

Of these 13 terms, only the semantic (metrics) layer computes answers; the others describe, identify, connect, remember or carry context to an agent ([Cube](https://cube.dev/blog/the-context-layer-needs-a-semantic-layer)).

| Term | What it is | What it is not | Example products |
|---|---|---|---|
| Semantic layer | Executable definitions of measures, dimensions and join paths that compile to correct SQL, DAX or MDX at query time ([dbt architecture](https://docs.getdbt.com/docs/use-dbt-semantic-layer/sl-architecture); [LookML](https://docs.cloud.google.com/looker/docs/what-is-lookml)) (both). | Not a glossary or catalog: a context source can describe a measure without executing it ([Atlan FAQ](https://docs.atlan.com/agents/faq/context-layer)) (Astra). MIT CISR uses a broader meaning that includes enterprise semantics ([MIT CISR](https://cisr.mit.edu/publication/2026_0501_SemanticLayer_LefebvreWixomLegnerVandermeulenBeath)) (Astra). | [dbt Semantic Layer](https://docs.getdbt.com/docs/use-dbt-semantic-layer/setup-sl), [Cube](https://docs.cube.dev/docs/introduction), AtScale, LookML, Power BI semantic models, [Snowflake semantic views](https://docs.snowflake.com/en/user-guide/views-semantic/overview), [Databricks metric views](https://docs.databricks.com/aws/en/metric-views/) |
| Context layer | Everything an agent needs to answer correctly: definitions, metadata, lineage, ownership, policies, canonical entities, documents and tribal knowledge ([a16z](https://a16z.com/your-data-agents-need-context/); [Atlan FAQ](https://docs.atlan.com/agents/faq/context-layer)). A stack of 12-14 components, not one product (Opus). | Not automatically an engine that computes numbers ([Cube](https://cube.dev/blog/the-context-layer-needs-a-semantic-layer)). Buying one category does not supply the others ([Palantir](https://www.palantir.com/docs/foundry/architecture-center/ontology-system); [Ramp](https://support.ramp.com/how-glass-works/)) (Astra). | Atlan Context Lakehouse ([Atlan](https://atlan.com/know/context-layer-stopped-being-theoretical-activate-2026/)), [Snowflake Horizon Context](https://docs.snowflake.com/en/release-notes/2026/other/2026-10-12-horizon-context-preview) (preview), Databricks Genie Ontology ([Databricks](https://databricks.com/blog/whats-new-unity-catalog-data-ai-summit-2026)), Google Knowledge Catalog ([Google Cloud](https://cloud.google.com/blog/products/data-analytics/introducing-the-google-cloud-knowledge-catalog)), AWS Context ([AWS](https://aws.amazon.com/blogs/machine-learning/context-intelligence-for-your-data-and-ai-agents-at-scale/), "coming soon") |
| Metrics layer | The metric-only core of a semantic layer: each KPI defined once in code, versioned and reused by every tool. Airbnb's Minerva held 12,000+ metrics in one reviewed repository ([Airbnb](https://medium.com/airbnb-engineering/how-airbnb-achieved-metric-consistency-at-scale-f23cc53dea70)) (Opus). | Not an entity model or a document store. It cannot join retailer sales to SAP shipments without canonical identifiers (Opus synthesis). | [MetricFlow](https://www.getdbt.com/blog/dbt-labs-affirms-commitment-to-open-semantic-interchange-by-open-sourcing-metricflow), [Databricks metric views](https://docs.databricks.com/aws/en/uc-semantics/metric-views/), [Snowflake semantic views](https://docs.snowflake.com/en/user-guide/views-semantic/semantic-view-yaml-spec), [Apache Ossie](https://ossie.apache.org/) (interchange format) |
| Ontology | Typed business objects, properties, relationships, rules and, in some products, actions, bound to source data ([Palantir](https://www.palantir.com/docs/foundry/ontology/core-concepts/)) (both). | Not a query engine: Fabric IQ's ontology "isn't itself a general-purpose data-query engine" ([Microsoft Learn](https://learn.microsoft.com/en-us/fabric/iq/ontology/overview)). One vendor's ontology is not automatically interchangeable with RDF/OWL ([Palantir](https://www.palantir.com/docs/foundry/architecture-center/ontology-system)) (Astra). | Palantir Ontology, Fabric IQ ontology (preview), SAP Knowledge Graph and Ontology Manager (beta planned Q1 2027, [ERP Today](https://erp.today/sap-teched-2026-whats-rolling-out-and-whats-planned-through-2027/)), [TopBraid EDG](https://docs.topquadrant.com/9.0/user_guide/guidance_specific_to_asset_collection_type/working_with_ontologies/working_with_ontologies.html), [Timbr](https://timbr.ai/doc/docs/getting-started/intro-timbr/) |
| Knowledge graph | A graph of entities and relationships, often with instance data and provenance, that agents traverse for multi-hop questions ([Neo4j](https://neo4j.com/product/knowledge-layer/); [Cognite](https://www.cognite.com/en/industrial-knowledge-graph)). | Not necessarily a copy: virtual graphs translate queries to the sources ([Stardog](https://docs.stardog.com/virtual-graphs/)) (both). Not a finance-grade calculation engine ([Glean](https://docs.glean.com/security/knowledge-graph)) (Astra). | Neo4j, Stardog, Cognite Data Fusion, Glean, [Microsoft GraphRAG](https://microsoft.github.io/graphrag/), [Kinaxis semantic graph](https://www.kinaxis.com/en/semantic-graph) |
| Data catalog | An inventory of tables, columns, owners, classifications, lineage and usage, searchable by people and agents ([Azure Architecture Center](https://learn.microsoft.com/en-us/azure/architecture/example-scenario/dataplate2e/data-platform-end-to-end)). | Descriptive only: it does not compute answers (Opus). A catalog entry describing an inventory table is not current inventory (Astra). | Unity Catalog, Snowflake Horizon, Purview Unified Catalog, Google Knowledge Catalog, [Atlan](https://docs.atlan.com/agents/how-tos/build-a-context-layer), Collibra, [Alation](https://alation.github.io/agent-studio-docs/integrations/mcp/using-the-mcp-server/), [DataHub](https://datahub.com/?p=15016) |
| Business glossary | Agreed meanings of business words, such as "net revenue" or "case fill rate", each linked to the assets that implement it ([Collibra University](https://cdn-university.collibra.com/wp-content/COOK/Business-Glossary-Case_360780.html)). | Not executable: two dashboards can still compute "net revenue" differently (Opus). A glossary can document disagreement without resolving the calculation (Astra). | Collibra, Purview glossary, Atlan, Alation |
| Data dictionary | Technical descriptions at column and table grain: field, type, key and update cadence, for example column `NETWR` in table `VBAP` (both). | Not business meaning, entity identity or a calculation. It answers "what is this field?", not "what do we mean?" (both). | Unity Catalog, Snowflake Horizon, Purview Data Map, DataHub; SAP DDIC schemas feed Google Cortex ([Google Cloud](https://docs.cloud.google.com/cortex/docs/overview)) |
| MDM | Master data management: one identifier per customer, product, supplier or location, with golden records, crosswalks and survivorship rules ([AWS Entity Resolution](https://docs.aws.amazon.com/entityresolution/latest/userguide/what-is-service.html); [SAP MDG](https://www.sap.com/products/data-cloud/master-data-governance.html)) (both). | Not a metric definition: MDM answers "which product?", not "how is net revenue calculated?" ([Reltio](https://www.reltio.com/products/entity-resolution/)) (Astra). | Reltio (SAP since May 2026, [SAP](https://news.sap.com/2026/05/sap-completes-acquisition-of-reltio/)), Informatica (Salesforce), Stibo, [Profisee](https://profisee.com/press-release/profisee-brings-end-to-end-master-data-management-fully-into-microsoft-fabric-at-fabcon-2026-adds-fabric-open-mirroring-support-and-copilot-connectivity-via-profisee-mcp-server/), SAP MDG, AWS Entity Resolution |
| Data virtualisation | A query engine that leaves data at source and pushes "filters, joins, and calculations" to it at run time ([Denodo](https://www.denodo.com/en/data-virtualization/overview)) (both). | Not free of source load or latency ([Databricks](https://docs.databricks.com/aws/en/query-federation/)). Its caches are copies with expiry rules ([Denodo](https://www.denodo.com/en/denodo-platform/denodo-platform)) (Astra). Not the same as a zero-copy share. | Denodo, Starburst/Trino ([Starburst](https://www.starburst.io/blog/starburst-galaxy-ai-on-iceberg-foundations/)), Dremio (SAP), Databricks Lakehouse Federation, Timbr, Stardog virtual graphs |
| Data product | A curated, owned dataset published for reuse, with a named owner accountable for quality and time-to-use ([data mesh principles](https://martinfowler.com/articles/data-mesh-principles.html)). | Not a full semantic model: a share moves data and some metadata, not the definitions ([Databricks](https://docs.databricks.com/aws/en/delta-sharing/)) (Opus). | SAP BDC data products ([SAP](https://news.sap.com/2025/02/sap-databricks-open-bold-new-era-data-ai/)), [AWS CPG Data Products guidance](https://aws.amazon.com/solutions/guidance/cpg-data-products-on-aws/), Starburst data products, Crisp harmonised retail data ([Crisp](https://www.gocrisp.com/our-platform)) |
| Context graph / agent memory | A context graph links operational things (services, teams, incidents, code, datasets) for agents; Uber's has 24 million nodes ([Uber](https://www.uber.com/blog/efficient-software-factory/)) (both). Memory keeps scoped user, team and company context and past corrections ([Ramp](https://support.ramp.com/how-glass-works/); [OpenAI](https://openai.com/index/inside-our-in-house-data-agent/)). | Not approved corporate knowledge: a conversation-derived hypothesis should not overwrite a definition (Astra). Cube places memory in the agent harness, outside the semantic layer ([Cube](https://cube.dev/blog/the-context-layer-needs-a-semantic-layer)) (Opus). | Uber ContextGraph, OpenAI data agent memory, Ramp Glass, [Microsoft Work IQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/), Neo4j Context Engine graph-native memory ([Neo4j](https://neo4j.com/press-releases/neo4j-context-engine/), private preview) |
| MCP | Model Context Protocol: JSON-RPC 2.0 between hosts, clients and servers; servers expose resources, prompts and tools ([MCP spec](https://modelcontextprotocol.io/specification/2025-11-25)). | Not a context layer and not access control: the spec says implementors "SHOULD" build consent and access controls (Opus). A connector is not proof of zero storage ([dbt MCP](https://docs.getdbt.com/docs/dbt-ai/about-mcp)) (Astra). | MCP servers from dbt, Cube, AtScale, Looker, Atlan, Starburst (Opus), plus [Kyvos](https://docs.support.kyvosinsights.com/wiki/spaces/KD20269/pages/1496881576/Kyvos%2BModel%2BContext%2BProtocol%2BMCP%2BServer), [GoodData](https://www.gooddata.ai/docs/cloud/ai/mcp-server/) and Alation (Astra) |

The terms overlap because two framings compete. a16z say the context layer "should essentially become a superset" of the semantic layer ([a16z](https://a16z.com/your-data-agents-need-context/)), while Cube says the semantic layer is "the one part that actually executes" inside it ([Cube](https://cube.dev/blog/the-context-layer-needs-a-semantic-layer)) (Opus). They describe the same stack from different seats. MIT CISR and Atlan stretch both terms wider still, so ask what is represented, executed and governed ([MIT CISR](https://cisr.mit.edu/publication/2026_0501_SemanticLayer_LefebvreWixomLegnerVandermeulenBeath); [Atlan FAQ](https://docs.atlan.com/agents/faq/context-layer)) (Astra).
