The short version

You already have the shape of it verified

Claude Code Desktop runs its engine on hlab. The Codex desktop app on x1eg3 is already SSH-connected to hlab: its app-server has been running there for two days. The agents are not on the laptop.

The slowdown is not Codex compute two causes

It is the ChatGPT/Codex Windows app shell (documented process-scan and git.exe storms plus Defender load, even when idle) and the laptop's own Thunderbolt fault loop.

Herdr: no, not as your cockpit terminal only

It is tmux rewritten in Rust with an agent-state sidebar and a ding. One host per client, no GUI. Both desktop apps already give you per-session state, worktrees and finish notifications.

KVM: insurance, not throughput optional

A GL.iNet Comet PoE plus ATX board (about £125) joins your tailnet and rescues a hung or unbootable P520 from anywhere. It adds zero agents.

The real lesson is parallelism + a ding do this

The P520 can host 16 agent sessions itself. What is missing is a notification that reaches you anywhere and one view of "who needs me". That is hooks in both tools, not hardware.

KVM over IP: advantages and costs

"I want a similar KVM/IP setup with my P520 using the Tailscale I am already using. What are the advantages? What are the costs?"

Advantage: it works when nothing else does. Everything you use today is in-band: it needs the kernel, networking, tailscaled and sshd alive on the P520. A KVM is a fake monitor plus fake keyboard with its own network stack. The GL.iNet Comet runs Tailscale itself, so it becomes its own tailnet node and is reachable from the laptop even when the P520's Tailscale is dead. It gives you the BIOS screen, GRUB, a hung box, a reinstall from a mounted ISO, and a hard reset or cold power-on through the ATX header. It adds no agent capacity at all.

When it actually earns its keep

  • The box hangs or wedges on memory: hard reset via the ATX board and watch it POST.
  • A kernel or NVIDIA driver update leaves it at GRUB rescue, an initramfs prompt, a fsck question or emergency mode.
  • Networking or Tailscale itself breaks on the host, which removes every in-band path at once.
  • BIOS changes, firmware updates, Secure Boot toggles, "power on after AC loss".
  • Cold power-on after a power cut when Wake-on-LAN does not fire.

Honest estimate for a headless dev server on a home LAN: a handful of uses a year. Today each of those means waiting until you are home or asking someone to press the button and describe the screen. With a Comet it is a two-minute fix from the laptop wherever you are, and risky remote work such as driver upgrades becomes safe to do while travelling. Cheaper partial cover: a smart plug on the tailnet plus "power on after AC loss" in the BIOS gives you the hard-reboot half for about £10 with no screen.

Should you use Herdr?

"Should I use Herdr given I am doing a lot of design work and finding the UIs far easier than the CLI in Warp?"

No, not as your cockpit. Herdr is a terminal multiplexer, tmux rewritten in Rust, with a sidebar that marks each pane working, blocked, idle or done and plays a sound. It is free and well made, but it is terminal-only, one host per client, and it would cost you the voice input, paste, split view, dispatch and phone surfaces of the desktop apps in exchange for a state sidebar you already have. Keep it in reserve for one narrow job on hlab, described below.

What it is

herdr.dev, Apache-2.0, free, no account or telemetry, single 10 MB Rust binary for Linux, macOS and Windows. Made by Can Celik (Herdr Inc., YC F26). Not a 37signals project; DHH contributes config PRs and Omarchy 4 ships it.

How it knows an agent is blocked

Claude Code hooks where available (authoritative), otherwise pattern manifests matched against the bottom of the screen. 21 agents detected including Claude Code, Codex, Gemini CLI and Kiro CLI.

Multi-machine reality

One client attaches to exactly one server. herdr --remote user@host streams a remote server's UI back. There is no multi-host view yet; the maintainer calls it top priority but it needs a rewrite. DHH's "multiple Herdr setups" means one per mini PC.

GUI options

None official. Community web and phone front-ends exist (Herdr Studio, Collie as a PWA over Tailscale serve, Moshi on iOS).

The workflow with Claude Code Desktop and Codex Desktop

"What would the workflow look like if I used Claude Code Desktop and Codex Desktop instead of Herdr?"

Claude Code Desktop stays the cockpit. Codex is a second workforce reached two ways. One notification bus on hlab is the ding. The parts DHH gets from Herdr map onto features the two apps already have; the only new wiring is hooks that post to one channel so it does not matter which app started a session or which device you are holding.
1. Open the cockpitClaude Code Desktop, hlab environment. Ctrl+N per task; each lands in its own worktree. Start four to eight.
Split view with Ctrl+click for two at once.
2. Delegate to CodexAny bounded chunk (a migration, test scaffolding, a refactor) goes to Codex from inside the Claude session, so Codex threads multiply with no second GUI.
Today's pattern, kept and scaled.
3. Talk to Codex directlyFor design work where you want Codex in front of you, use the light path from the next section: VS Code Remote-SSH with the Codex extension, or the app with its scanning triggers removed.
4. Get the dingHooks in both tools post blocked and done events to ntfy or Telegram. Claude's mobile push covers permission prompts when Remote Control is on.
Approve from the phone or come back to the Desktop.
5. Review and shipDesktop diff view for Claude sessions, Codex PR review for Codex threads, then the ship ledger for anything visible.

The wiring, all on hlab, nothing on the laptop

  • Claude Code hooks (shared by CLI and Desktop): a Notification hook on permission_prompt, idle_prompt, agent_needs_input and agent_completed, plus a Stop hook, each posting a one-line message to an ntfy topic served over Tailscale or to Telegram.
  • Codex hooks in ~/.codex/hooks.json: PermissionRequest, Stop, SubagentStop and Interrupt events, run async, posting to the same endpoint. Codex's older notify setting only fires on turn completion, so use hooks.
  • Phone steering: run claude remote-control --spawn worktree --capacity 8 inside tmux on hlab. Those sessions show up in the Claude web and mobile apps with a green dot and push "action required" notifications. Codex Remote pairs the phone to the Codex app by QR for the same on that side.
  • Channels: Claude Code's Telegram channel plugin relays permission prompts into Telegram so you can approve without opening anything.
  • Who needs me: short term, the Desktop sidebar filtered by status plus the ntfy feed. Medium term, a small page on the launch board that reads both hook feeds. That page is Herdr's sidebar, cross-tool and in the browser.

Using Codex much more without the laptop drag

"Codex is slowing down my laptop enormously … I want to start using Codex more, but don't want all the issues of it slowing down my laptop."

The agent is already on hlab. The drag comes from the Windows app shell and from the laptop itself. OpenAI's own issue tracker documents the unified ChatGPT/Codex app on Windows running process-inventory scans about 26 times a minute and spawning hundreds of git and console processes a minute for repo discovery, which produced system-wide input lag; Defender adds 5 to 17 percent CPU while the app is open and exclusions do not help. Separately, x1eg3's Thunderbolt controller is in a fault loop. Neither is fixed by moving compute, because the compute has already moved.

Next steps, in order

  1. Fix the x1eg3 Thunderbolt fault (Lenovo Thunderbolt firmware, driver and BIOS via System Update). This is dragging the laptop whatever you run.
  2. On hlab: upgrade Codex CLI to 0.153.4, add the ntfy or Telegram hooks for both Claude Code and Codex, and turn on Claude's mobile push under Remote Control.
  3. Set the Codex model mix: Astra for hard problems, Sol for general, Luna for bulk. Keep delegating from Claude Code by default.
  4. Trial VS Code Remote-SSH with the Codex extension for direct Codex sessions. Only open the Windows Codex app for its exclusive features, and never point it at a folder of many repos.
  5. Decide on the Comet PoE plus ATX board. Buy it only if the P520 must survive unattended while you travel. Enable Intel AMT in the BIOS for free power control either way.
  6. Leave Herdr alone. Revisit if it gains a multi-host view or if a second agent machine appears.
