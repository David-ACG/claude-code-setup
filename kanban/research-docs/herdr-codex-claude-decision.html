Decision brief · 19 September 2026

Herdr should be the control room, not the crew.

Keep Codex planning and independently judging the work. Keep Claude Code building and self-checking it. Pilot Herdr underneath them for persistent terminals, live status, session recovery, and agent control.

✓
Recommendation: a bounded Herdr pilot.
Do not replace Beads, the GWTH cockpit, Codex, Claude Code, worktrees, or evidence-based QA.

One layer, one job

The biggest failure mode would be asking Herdr to become a model, task tracker, QA gate, and project dashboard. Its value is narrower and cleaner.

Authority

Codex

Plan · orchestrate · independently inspect · decide whether evidence is enough.

Builder

Claude Code

Implement · test · self-review · return a structured evidence report.

Substrate

Herdr

Host terminals · retain sessions · show coarse state · prompt, wait, and read.

Truth

Git + tests + previews

Prove what changed and whether it works. A green “done” badge is not proof.

Memory

Beads

Remain the durable queue, dependency graph, status record, and handoff memory.

Decision surface

GWTH cockpit

Keep project priority, questions, reviews, approvals, and shipping state human-readable.

Where Herdr fits

It improves supervision and recovery in the middle of the loop. It does not define intent or certify the result.

What “more insight” really means

Herdr can expose

  • Live and recent terminal output
  • Prompts, permission dialogs, and visible blockers
  • Working, blocked, done, idle, or unknown state
  • Session identities and retained scrollback
  • Notifications and SSH-resilient background work
  • Programmatic prompt, wait, read, and focus controls

Herdr cannot establish

  • A model’s private chain-of-thought
  • That “done” means correct
  • That Claude’s self-review was independent or complete
  • Conflict-free parallel edits without worktrees
  • An immutable task-to-diff-to-test audit trail
  • A security boundary between same-user processes
A better target than watching thoughts: observe the contract, actions, diff, tests, self-review findings, independent findings, and final verdict.

Why use it — and why not

Advantages

Less terminal hunting

Named agents, roll-up state, jump-to-pane navigation, and notifications make long-running work much easier to supervise.

Disadvantage

Another control plane

Configuration, updates, logs, keybindings, and failure modes become part of the operating environment.

Advantages

Vendor-neutral continuity

Claude and Codex keep their native CLIs, sessions, subscriptions, and different strengths. Herdr does not force one model family.

Disadvantage

State is advisory

Claude and Codex lifecycle state is currently inferred from the visible screen. An unfamiliar prompt may look idle rather than blocked.

Advantages

Automation seam

The CLI and local socket API are a practical bridge from Codex or the GWTH cockpit to real persistent agent sessions.

Disadvantage

Parallelism amplifies mistakes

Without contracts and worktrees, more agents mean more collisions, stale assumptions, port conflicts, duplicated effort, and spend.

A deliberately small pilot

Five reversible, non-deployment tasks are enough to learn whether Herdr removes real friction.

Pin and install on hlabUse a stable published binary. Keep the current workflow intact as the rollback path.
Start with three panesClaude implementer, Codex reviewer, and deterministic checks. Add roles only when evidence justifies them.
Isolate every implementationOne worktree and bounded task contract per bead. Herdr is not conflict isolation.
Require two QA layersClaude self-QA before handoff; Codex reruns proportionate checks from the contract and repository state.
Measure supervision, not noveltyTrack time-to-notice blockers, complete evidence reports, collisions, model usage, and whether David finds the view clearer.
Success

Keep it when…

Blocked sessions surface sooner, terminal switching falls, evidence quality holds, and the combined Herdr/cockpit view is easier to understand.

Stop

Narrow it when…

Status is often wrong, orchestration glue is brittle, worktree discipline worsens, or live monitoring consumes more attention than evidence review.

Questions the pilot must answer

Is Herdr actually the missing piece?
Possibly. If David mainly wants a post-hoc account of Claude’s activity, the current JSONL transcript parser and cockpit are closer to the answer. Herdr earns its place only if live supervision, session persistence, and control matter.
Would Codex and Claude Code still be used?
Yes. Herdr has no model. It runs the installed CLIs and gives people or other agents a better way to operate them.
Should Claude also QA itself?
Yes, as a first line. Require a diff review, tests, and explicit risks. Keep the final QA independent: Codex should judge the task contract and evidence, not merely approve Claude’s narrative.
Should Herdr replace the GWTH cockpit?
No. Herdr knows live terminal state. The cockpit and Beads know project meaning, priority, approvals, and shipping state. Feed Herdr state into the cockpit later if the pilot succeeds.
